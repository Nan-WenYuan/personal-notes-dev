# 番茄钟与四象限任务联动设计

## 建议范围

保持两页现有分工：四象限安排任务，番茄钟执行一次专注。共用现有任务 UUID，不增加一套任务系统，也不把笔记正文变成任务。

## 使用流程

1. 四象限每条未完成任务提供小型“开始专注”入口；点击打开番茄钟并关联该任务。
2. 番茄钟圆环上方显示当前任务，支持从未完成四象限任务中选择，也允许“不关联任务”。
3. 每完成一个番茄，专注记录保存 taskId 与当时的 taskTitle，四象限对应行显示累计番茄数和专注时长。
4. 自动休息期间保留关联任务，下一轮专注继续同一任务。
5. 任务勾选完成与番茄完成分别处理。勾选当前任务时，提示“停止当前专注”或“继续本轮”，不直接给任务加完成番茄。

## 冲突处理

- 切换另一任务时，未完成专注先选择取消切换或放弃本轮并开始新任务，避免一轮时间记到多个任务。
- 任务重命名通过 UUID 保持关联，历史记录保留当时标题；删除任务不删除专注历史。
- 任务移到其他象限不影响关联，番茄钟只读取当前任务所属象限。
- 编辑、删除专注记录后，日历统计与任务累计统计使用同一 records 集合重新汇总。
- 已完成任务不出现在新专注选择器中；重新打开任务后可继续专注。
- 普通番茄钟继续支持不关联任务，避免为了计时必须先建任务。

## 数据兼容

- FocusRecord 增加可选 taskId、taskTitle；旧记录默认为不关联。
- TimerState 增加可选 activeTaskId、activeTaskTitle，开始本轮时冻结到会话字段，完成后写入记录。
- 四象限任务不保存冗余累计数量，按 taskId 从番茄钟 records 汇总，防止两份计数不一致。
- 后端 JSON 保持可选字段和默认值，沿用四象限.json、番茄钟.json。

## 验证重点

任务重命名、删除、移象限、勾选完成；中途切任务；自动轮换和退出恢复；历史记录修改删除后的计数同步。

本文件是研究方案，此轮未实现任务联动。
